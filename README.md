# 🔥 HuoYu | 无尽火域

HuoYu 是一个可部署到 Vercel 的个人主页站点。前台展示个人资料、技能、项目、GitHub、Steam、WeGame、网易云音乐、WakaTime 等数据；后台用来维护站点资料、项目展示和页脚内容。

## 🧩 需要部署的服务

| 服务 | 是否必需 | 用途 |
| --- | --- | --- |
| Vercel | 必需 | 当前主站部署平台 |
| Upstash Redis | 必需 | 使用 Upstash 免费云 Redis 或 Vercel Marketplace 集成，保存后台配置、项目配置和缓存数据 |
| GitHub Actions | 推荐 | 当前用于每 8 小时自动同步 GitHub 项目元数据 |
| Tolgee | 可选但推荐 | 当前使用自托管实例 `https://tolgee.viper3.top` 管理多语言翻译 |
| MTranServer | 可选 | 当前使用自建接口 `https://tran.viper3.top` 批量补全本地语言包 |

最小可运行只需要 Vercel + Upstash Redis。当前站点的翻译维护使用自托管 Tolgee 和 MTranServer；前台运行时仍优先读取本地语言包，所以翻译服务短暂不可用也不会影响页面展示。

## 🚀 部署顺序

### 1. 准备项目 🧱

```bash
git clone git@github.com:Flames1217/HuoYu.git
cd HuoYu
pnpm install
cp .env.example .env.local
```

### 2. 创建 Redis 🗄️

创建一个 Upstash Redis 云实例，免费套餐就可以跑这个站点。你可以直接在 Upstash 控制台创建，也可以在 Vercel Marketplace 里添加 Upstash 集成。

在 Upstash 控制台创建时，填这组变量：

```env
UPSTASH_REDIS_REST_URL=your_upstash_redis_rest_url
UPSTASH_REDIS_REST_TOKEN=your_upstash_redis_rest_token
```

如果通过 Vercel Marketplace 连接 Upstash，通常会自动注入这组变量：

```env
KV_REST_API_URL=your_kv_rest_api_url
KV_REST_API_TOKEN=your_kv_rest_api_token
```

### 3. 配置主站环境变量 🔐

本地 `.env.local` 和 Vercel Project Settings -> Environment Variables 都需要配置：

```env
PASSWORD=your_admin_password
NEXTAUTH_SECRET=your_random_nextauth_secret
CRON_SECRET=your_random_cron_secret
GITHUB_TOKEN=your_github_token
```

说明：

- `PASSWORD`：后台登录密码。
- `NEXTAUTH_SECRET`：NextAuth 会话密钥，可用 `openssl rand -base64 32` 生成。
- `CRON_SECRET`：保护 GitHub 项目自动同步接口。
- `GITHUB_TOKEN`：同步项目仓库、仓库改名识别和 GitHub 贡献数据。

`GITHUB_TOKEN` 建议使用 GitHub fine-grained token，只给当前账号公开仓库读取权限即可。

### 4. 部署到 Vercel ▲

把仓库导入 Vercel，填好上面的环境变量，然后部署。

部署成功后访问：

- 前台：`https://viper3.top/cn`
- 后台：`https://viper3.top/cn/admin`，其他语言后台入口同样可用，例如 `/en/admin`、`/ja/admin`

登录后台后按顺序配置：

1. 个人资料：昵称、头像、标题、社交链接、技能。
2. 项目管理：同步 GitHub 仓库，勾选要在前台展示的项目。
3. 页脚管理：备案、自定义文本和链接。

后台配置会保存到 Redis，默认 key 是：

```env
SETTINGS_REDIS_KEY=huoyu:settings
```

同一个 Redis 跑多个站点时，把 `SETTINGS_REDIS_KEY` 改成不同值。

### 5. 配置 GitHub 项目自动同步 🔁

项目展示会同步 GitHub 仓库名、简介、语言、topics、Star/Fork、GitHub 地址和最近更新时间。同步逻辑使用 GitHub 仓库 ID，仓库改名后仍会保留后台的展示开关、排序和演示地址。

仓库里已经内置 GitHub Actions：

```text
.github/workflows/sync-github-repos.yml
```

它每 8 小时请求一次：

```text
GET /api/cron/github-repos
Authorization: Bearer your_random_cron_secret
```

在 GitHub 仓库 Settings -> Secrets and variables -> Actions 中添加：

| Secret | 示例 |
| --- | --- |
| `SITE_URL` | `https://viper3.top` |
| `CRON_SECRET` | 和 Vercel 里的 `CRON_SECRET` 一致 |

Vercel Hobby 免费版 Cron 通常只支持每天一次，所以默认用 GitHub Actions 实现每天 3 次同步。

## 🌐 翻译服务

### Tolgee 🦎

当前使用自托管 Tolgee：`https://tolgee.viper3.top`。自托管可以避开 Tolgee Cloud 免费版的字符串数量限制，适合把本地语言包完整同步进去。

服务端同步变量只放 `.env.local` 或部署平台环境变量，不要提交到仓库：

```env
TOLGEE_API_URL=https://tolgee.viper3.top
TOLGEE_API_KEY=your_tolgee_server_api_key
TOLGEE_PROJECT_ID=1
```

如果只是让站点正常显示多语言，不需要配置 `NEXT_PUBLIC_TOLGEE_*`。HuoYu 会优先使用 `lib/locales/` 里的本地语言包。

如果要在前台连接 Tolgee 在线调试，可以额外配置项目级前端 API Key：

```env
NEXT_PUBLIC_TOLGEE_API_URL=https://tolgee.viper3.top
NEXT_PUBLIC_TOLGEE_API_KEY=your_tolgee_project_client_key
NEXT_PUBLIC_TOLGEE_PROJECT_ID=1
```

不要把个人访问令牌、PAT 或服务端 key 放进 `NEXT_PUBLIC_TOLGEE_API_KEY`。

### MTranServer 🧠

当前使用自建 MTranServer 接口：`https://tran.viper3.top`。它只在维护语言包时使用，主站运行不依赖它。

```env
MTRAN_API_URL=https://tran.viper3.top
MTRAN_API_KEY=your_mtran_api_key
```

HuoYu 的脚本会调用：

```text
POST /translate/batch
Header: Authorization: your_mtran_api_key
```

MTranServer 不建议部署在 Vercel Serverless。推荐放 VPS、NAS、Docker 主机或内网服务器，再通过 HTTPS 反代出来。

## 📝 翻译维护流程

本地语言包位置：

```text
lib/locales/cn.json
lib/locales/en.json
lib/locales/es.json
lib/locales/fr.json
lib/locales/ja.json
```

推荐流程：

```bash
pnpm translate:fill-en-defaults
pnpm translate:fill-en
node scripts/translate-locales-from-en.mjs
```

第一次把本地语言包导入一个新的自托管 Tolgee 项目时运行：

```bash
TOLGEE_SKIP_NEW_KEYS=false node scripts/sync-tolgee-direct.mjs
```

之后如果只想覆盖 Tolgee 里已有 key，可以直接运行：

```bash
node scripts/sync-tolgee-direct.mjs
```

如果只想更新 Tolgee 里已经存在的翻译记录，不新增任何语言记录：

```bash
TOLGEE_SYNC_EXISTING_TRANSLATIONS_ONLY=true node scripts/sync-tolgee-direct.mjs
```

## ⚙️ 环境变量总览

### 必填 ✅

| 变量 | 说明 |
| --- | --- |
| `PASSWORD` | 后台登录密码 |
| `NEXTAUTH_SECRET` | NextAuth 会话密钥 |
| `CRON_SECRET` | 自动同步 GitHub 项目的接口密钥 |
| `UPSTASH_REDIS_REST_URL` / `KV_REST_API_URL` | Redis REST URL，二选一 |
| `UPSTASH_REDIS_REST_TOKEN` / `KV_REST_API_TOKEN` | Redis REST Token，二选一 |

### 推荐 ✨

| 变量 | 说明 |
| --- | --- |
| `GITHUB_TOKEN` | GitHub 仓库同步和贡献数据 |
| `SETTINGS_REDIS_KEY` | Redis 配置 key，默认 `huoyu:settings` |
| `NEXT_PUBLIC_FEED_URL` | RSS 区块 feed 地址 |

### 第三方数据源 📡

| 变量 | 说明 |
| --- | --- |
| `STEAM_API_KEY` | Steam Web API Key |
| `STEAM_USER_ID` | Steam 64 位用户 ID |
| `NETEASE_USER_ID` | 网易云音乐用户 ID |
| `NETEASE_MUSIC_U` | 网易云音乐 Cookie 中的 `MUSIC_U` |
| `NETEASE_API_BASE_URL` | 网易云音乐 API 服务地址，默认 `https://api-cloudmusic.viper3.top` |
| `WAKATIME_API_KEY` | WakaTime API Key |
| `WEGAME_TGP_ID` | WeGame Cookie 中的 `tgp_id` |
| `WEGAME_COOKIE` | WeGame 完整 Cookie |

### 翻译维护 🛠️

| 变量 | 说明 |
| --- | --- |
| `TOLGEE_API_URL` | Tolgee 服务端地址 |
| `TOLGEE_API_KEY` | Tolgee 服务端 API Key，不要暴露到前端 |
| `TOLGEE_PROJECT_ID` | Tolgee 项目 ID |
| `TOLGEE_SKIP_NEW_KEYS` | 设为 `false` 时允许向 Tolgee 新增 key |
| `TOLGEE_SYNC_EXISTING_TRANSLATIONS_ONLY` | 设为 `true` 时只更新已存在翻译记录 |
| `TOLGEE_SYNC_CONCURRENCY` | Tolgee 同步并发数，默认 `8`；自托管实例压力大时可设为 `1` |
| `MTRAN_API_URL` | MTranServer 地址 |
| `MTRAN_API_KEY` | MTranServer API Key |
| `MTRAN_BATCH_SIZE` | 批量翻译大小 |
| `TARGET_LOCALES` | 指定要补的语言，例如 `es,fr,ja` |

## 🧭 维护规则

改动以下内容时，要同步更新 README 和 `.env.example`：

- 环境变量、Secrets、Token。
- 外部服务部署方式。
- GitHub Actions、Cron、Webhook、受保护接口。
- 翻译脚本、Tolgee 同步策略、MTranServer 调用方式。
- Redis 数据结构、后台配置项、项目同步规则。

## ⚠️ 注意事项

- `.env.local`、Cookie、Token 和 API Key 不要提交到仓库。
- `NEXT_PUBLIC_*` 会暴露到浏览器，不能放服务端密钥。
- WeGame、网易云音乐 Cookie 可能过期，数据异常时先检查 Cookie。
- GitHub、Steam、WakaTime 等接口有频率限制，生产环境建议保留缓存。
